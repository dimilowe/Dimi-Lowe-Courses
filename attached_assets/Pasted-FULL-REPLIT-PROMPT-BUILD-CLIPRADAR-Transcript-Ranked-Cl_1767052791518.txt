GOAL
Build a new tool named “ClipRadar” that:
1) Takes a YouTube URL
2) Uses our existing “YouTube Transcript” fetcher/util to retrieve a timestamped transcript (we already have this tool working somewhere in the codebase)
3) Runs a transcript-only “clip detection” scan:

5) Provides exports:
   - CSV (start,end,title,caption,score,category)
   - YouTube timestamps list
   - Marker CSV (simple name/description/in/out)
6) Adds ClipRadar into the tool registry + tools DB table + global_urls table so it shows up and can be indexed/de-indexed like other tools.

STEP 3 — CLIP DETECTION LOGIC (TRANSCRIPT-ONLY)

normalizeTranscript.ts
Input: transcript[] of {start,end,text}
- Trim text, drop empties
- Sort by start
- Merge segments if:
  - gap between current.start and prev.end <= mergeGapSeconds OR
  - current duration < 1.2s
- When merging: concatenate text with space, end = current.end
Output: normalized segments

scoreTranscript.ts
Compute score per segment (0–100) with reasons.
Signals:
1) Emotion keywords (high weight)
2) Event keywords (medium)
3) Audience-address phrases (medium-high)
4) Pacing spike proxy: words per second (light)
5) Punctuation density: ! ? (light-medium)
6) Repetition: repeated tokens within segment (light)
7) Reaction Stack bonus: if emotion+event appear within a 12s neighborhood, boost

Use dictionaries:
- emotionWords: ["no way","let's go","holy","insane","bro","wtf","omg","clutch","crazy","yo","wow","nah","bruh","are you kidding","i'm done","this game"]
- eventWords: ["killed","downed","knocked","headshot","ace","1v","wipe","team wipe","win","won","gg","final","last","rank","promo","overtime","plant","defuse","zone","circle","boss"]
- audiencePhrases: ["watch this","look at this","listen","clip that","you're not gonna believe","did you see that"]

Style weights:
- balanced: defaults
- hype: boost emotion + event
- funny: boost audience + emotion
- rage: boost rage phrases + punctuation
- educational: boost phrases like "here's how", "do this", "tip", "strategy" (add a small educationalWords list)

Score formula (example; implement cleanly, easy to tweak):
base = 0
+ emotionHits * 18
+ eventHits * 12
+ audienceHits * 16
+ punctScore (0–10)
+ paceScore (0–10)
+ repetitionScore (0–6)
then clamp 0–100
Then apply reactionStackBonus (e.g. *1.15 or +10) if neighborhood qualifies, clamp again

Return:
{ ...segment, score, reasons, features: {emotionHits,eventHits,audienceHits,paceWps,punctCount} }

selectPeaks.ts
Input: scored segments
- Sort by score desc
- Select peaks where score >= minScore
- De-dup: once a peak chosen, suppress any segment whose start time is within ±standardWindow seconds of peakTime
- Continue until maxResults
Return ordered peaks with rank

buildWindows.ts
Input: peaks, options.windows
For each peakTime:
- short: [peakTime - short, peakTime + short]
- standard: ...
- long: ...
Clamp start >= 0 and end <= lastTranscriptEnd
Optionally snap to nearest transcript boundaries (start to nearest segment.start before, end to nearest segment.end after)

generateMetadata.ts
No LLM. Use rule templates:
- Determine category by strongest signal:
  - if rage phrases or many ?!/caps => rage
  - else if audience phrases => funny/hype depending on event presence
  - else if event+emotion => hype
  - else educational if educational words found
- titles: 3 options from templates per category
- captions: 2 short overlays (max 6 words) with emoji optional
Also include reasons from scoring.

exports.ts
Build:
- csv: header + one row per result using STANDARD window (or let user choose later; for v1 use standard)
- youtubeTimestamps: “MM:SS - Title”
- markersCsv: “name,description,in,out” with in/out as HH:MM:SS.mmm
Include score in description.

Provide helper formatTime functions.
