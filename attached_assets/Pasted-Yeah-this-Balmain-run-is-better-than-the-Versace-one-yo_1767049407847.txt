Fix #1: Sleeve parsing must treat “sleeveless” as atomic
Right now you’re splitting everything into single tokens and then doing naive inference.
Rule (hard):
If the URL/text contains "sleeveless" (or "no sleeve") → sleeve = sleeveless and stop.
Don’t let "short" override anything.
Drop-in sleeve resolver (client-side)
function resolveSleeve(tokens: string[]): "sleeveless" | "short sleeve" | "long sleeve" | null {
  const t = tokens.map(x => x.toLowerCase());

  // atomic first
  if (t.includes("sleeveless")) return "sleeveless";
  if (t.includes("long-sleeve") || (t.includes("long") && t.includes("sleeve"))) return "long sleeve";
  if (t.includes("short-sleeve") || (t.includes("short") && t.includes("sleeve"))) return "short sleeve";

  return null;
}
Extra: stop creating “short sleeve” from “short + sleeveless”
Your URL path is literally short-sleeveless-dress...
When you split on hyphens, you get short, sleeveless, dress.
If your code sees short and sleeve anywhere, it will misfire.
So enforce: if sleeveless exists, never output short sleeve.
Fix #2: Disambiguate “short” as length when dress is present
In fashion, “short” is ambiguous:
short dress (length)
short sleeve
If garment type is dress, treat “short” as length unless “short sleeve” is explicitly present.
function resolveLength(tokens: string[], garmentType: string | null): "mini" | "short" | "midi" | "maxi" | null {
  const t = tokens.map(x => x.toLowerCase());
  if (garmentType !== "dress") return null;

  if (t.includes("mini")) return "mini";
  if (t.includes("maxi")) return "maxi";
  if (t.includes("midi")) return "midi";
  if (t.includes("short")) return "short";

  return null;
}
