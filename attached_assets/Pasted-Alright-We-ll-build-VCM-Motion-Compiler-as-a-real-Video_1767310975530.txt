6) Boundary Contract: normalized and mandatory (hard gate)
Boundary Contract rule
Beat i>1 cannot start unless:
it has boundary_start.frame + boundary_start.state from beat i-1
Beat spec additions (stored in manifest.json)
Each beat must contain:
{
  "beat_id": "B02",
  "duration": { "target": 1.2, "min": 0.9, "max": 1.5 },
  "boundary": {
    "requires_prev": true,
    "prev_beat_id": "B01",
    "start_contract": {
      "frame_key": "beats/B01/boundary_end.frame.png",
      "state_key": "beats/B01/boundary_end.state.json"
    }
  }
}
7) Boundary frame extraction (automated, not optional)
In stage: boundary, after a beat clip is created:
probe duration
seek to duration - 0.05s
extract 1 frame to boundary_end.frame.png
if too dark/glitched, fallback to duration - 0.12 then -0.20
Do not ship V1 without this. Manual fallback is allowed, but automation must exist.
8) Validation (V1: practical, not research)
You don’t need Stanford-grade latent reuse on day 1. You need deterministic gates.
V1 Validator checks
Identity checks (frame-level):
hair color class (silver-white)
jacket present (black hooded leather silhouette)
dog tag/watch: required only on beats flagged must_show
World checks:
scene_id match (hard)
palette similarity (coarse)
Boundary checks:
compare beat i-1 end frame to beat i first frame:
camera angle bucket match
screen position bucket match
lighting direction bucket match
Output per beat: validate.report.json with PASS/WARN/FAIL.
If FAIL:
retry beat with tighter constraints
if still FAIL after max attempts → halt compile
