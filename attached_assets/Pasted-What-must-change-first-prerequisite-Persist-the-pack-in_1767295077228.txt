Assembler v1 behavior (Option A)
1) Download
Pull manifest.json
Pull frames/ folder into /tmp/video-assembler/{jobId}/frames
2) Normalize timing (do not skip this)
Read fps (default 60)
Convert each shot to integer frames:
duration_frames = max(1, round(duration_sec * fps))
Apply clamp:
if duration_sec > 3.0 → set to 3.0 (or 3.0 * fps frames)
Recompute seconds from frames:
duration_sec = duration_frames / fps
This prevents drift + fixes your “14s hold” from making outputs unusable.
3) Render with ffmpeg (simple + reliable)
You render a slideshow video from the frames, using per-frame durations.
The clean approach is to generate a concat list file (ffconcat).
Create /tmp/.../frames.ffconcat like:
ffconcat version 1.0
file frames/b001.jpg
duration 0.983333
file frames/b002.jpg
duration 0.400000
...
file frames/b011.jpg
duration 5.200000
file frames/b011.jpg
That last repeated file line is required by ffmpeg concat rules so the final duration applies.
ffmpeg command (no audio yet):
Input: ffconcat list
Output: mp4 at 720x720, 60fps, yuv420p
4) Upload
Upload /tmp/.../output.mp4 → video-assembler/{jobId}/output.mp4
5) Update job record
Store in meta_json:
duration_sec (final)
fps
resolution
total_frames (sum duration_frames)
ffmpeg_cmd (string for debugging)
clamp_applied (count of shots clamped)
