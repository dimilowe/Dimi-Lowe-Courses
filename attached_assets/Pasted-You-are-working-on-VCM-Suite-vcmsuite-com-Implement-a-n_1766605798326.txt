You are working on VCM Suite (vcmsuite.com). Implement a new global “Workspace” feature that stores and displays ALL user-generated tool outputs (“files”) across all Clouds, while keeping commerce “Saved Items” (wishlist) and “Purchased Items” separate.

HIGH-LEVEL GOAL
Add a new item in the profile dropdown called “Workspace” that links to a new page showing the user’s saved outputs across all tools/clouds. Also, update each Cloud’s “Recent files” panel so it reads from this same global Workspace data filtered by cloud.

NON-NEGOTIABLE PRODUCT RULES
1) Workspace = work outputs only (tool results, prompts, images, bundles, workflow runs).
2) Saved Items (wishlist) stays commerce-only (products to buy later). Do NOT mix.
3) Purchased Items stays commerce-only (entitlements/products). Do NOT mix.
4) Cloud pages can show “Recent files”, but those are just filtered views of the global Workspace.
5) Workspace supports: Recents, Search, Filter by Cloud, Sort by Recent/Updated, Star (Saved).

ASSUMPTIONS
- Use the existing auth system to identify the current user.
- Use the existing DB layer (Prisma or SQL). If Prisma exists, implement via Prisma; otherwise write SQL migrations and DB helpers.
- Keep the change minimal and safe. No breaking changes to existing saved-items commerce flow.

DATA MODEL
Create a new table/collection: workspace_items.

Minimum fields:
- id (uuid / cuid)
- user_id (fk to users)
- title (string, default derived from tool output)
- type (enum/string: ad_bundle, copy_output, prompt_output, image_asset, workflow_run, generic)
- cloud_id (string enum: creation, video, writing, files, monetize, intelligence, music, growth) OR null for global
- tool_id (string) optional
- workflow_id (string) optional
- is_starred (boolean default false)
- created_at, updated_at
- last_opened_at (nullable timestamp)
- preview_text (nullable) small snippet for list display
- payload_json (json) store the actual output data (prompt text, copy text, etc.)
Optional but nice:
- thumbnail_url (nullable) for image assets
- tags_json (json array)

Also create workspace_attachments if the app already uses a file storage abstraction:
- id
- workspace_item_id
- storage_key/url
- mime_type
- width/height nullable
- created_at

If you find an existing “recent files” table in any cloud, do NOT duplicate—migrate/bridge it into workspace_items or replace reads to point to workspace_items.

BACKEND/APIs
Implement endpoints (or server actions) for:
1) Create workspace item
   - POST /api/workspace/items
   - Body: { title?, type, cloud_id?, tool_id?, workflow_id?, preview_text?, payload_json, thumbnail_url? }
   - Server sets user_id, timestamps.

2) List workspace items (for current user)
   - GET /api/workspace/items?cloud_id=...&q=...&sort=recent|updated|name&starred=true|false&limit=&offset=
   - “recent” sorts by COALESCE(last_opened_at, updated_at) DESC.

3) Get single item
   - GET /api/workspace/items/:id
   - Must verify ownership by user_id.
   - Update last_opened_at on read (or only when “Open” is clicked).

4) Star/unstar
   - PATCH /api/workspace/items/:id
   - Body: { is_starred: boolean }

5) Delete (optional v1)
   - DELETE /api/workspace/items/:id
