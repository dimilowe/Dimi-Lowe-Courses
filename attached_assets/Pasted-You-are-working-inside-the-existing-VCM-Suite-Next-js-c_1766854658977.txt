========================================================
SERVER PIPELINE (BESPOKE, CLEAN MODULES)
========================================================
Create a server lib folder:
- /server/lib/buylens/

Modules:
1) intent.ts
Parse user query into:

type BuyLensIntent = {
  product_query: string;
  optimization: "cheapest" | "best_value" | "best_quality" | "fastest_shipping" | "unknown";
  market: "retail" | "resale" | "both";
  max_budget_usd?: number;
  condition?: "any" | "new" | "used";
  must_include_shipping_total: boolean;
  keywords_include?: string[];
  keywords_exclude?: string[];
};

Rules:
- “cheapest” => optimization=cheapest
- “best”, “top”, “recommend” => best_value unless quality is explicit
- “reseller”, “used”, “stockx”, “goat”, “ebay”, “grailed”, “poshmark”, “depop” => market=resale
- default market=both
Use the app’s existing LLM utility if present; if not, implement a simple deterministic parser first, then optionally enhance with LLM if keys exist.

2) robots.ts
- Fetch https://domain/robots.txt
- Determine if our UA is allowed to fetch target path
- Cache per domain for the run
- If disallowed => robots_blocked

3) discover.ts
MVP source discovery:
- Based on market, build a curated candidate domain list:
  retail: amazon (only if safe), bestbuy, walmart, target, manufacturer sites when obvious
  resale: ebay, stockx, goat, grailed, poshmark, depop (only where public pages exist)
- Generate a SMALL list of search URLs per domain using their public search query patterns (do not require auth).
- Do not add paid search APIs unless already present in repo + env. Keep it simple.

4) crawl.ts
Use Playwright (preferred). If Playwright is already used elsewhere, reuse that setup.
- Must set UA
- Must enforce timeouts and caps
- Must stop on captcha/bot block indicators and record as captcha
- Must never proceed to login/checkout paths (detect via URL patterns: /login, /signin, /checkout, /cart, etc. and skip)

5) extract.ts
Extraction strategy:
- Try JSON-LD Product/Offer first
- Then OpenGraph
- Then DOM heuristics for price/shipping
Return RawListing:

type RawListing = {
  url: string;
  domain: string;
  title?: string;
  price_usd?: number;
  shipping_usd?: number;
  total_usd?: number;
  condition?: "new" | "used" | "unknown";
  seller?: string;
  currency?: string;
  key_specs?: string[];
  confidence: number; // 0..1
  notes?: string;
};

No raw HTML storage.

6) normalize.ts
- Convert currency if obvious; if not, leave undefined
- total_usd = price + shipping if both known and must_include_shipping_total
- Respect max_budget_usd if provided

7) rank.ts
- cheapest => sort by total_usd else price_usd; stable tiebreaker by confidence DESC
- best_value => confidence DESC then total_usd ASC
- fastest_shipping => prefer known shipping_usd low; else stable by total_usd
Return 5–10 results.

8) explain.ts (optional but recommended)
Use LLM if available to generate:
- why (1 sentence)
- tradeoff (1 sentence)
No fluff. Must be grounded in extracted fields.
