✅ Your plan, approved (with 3 adjustments)
1) DB: workspace_items table
Do it. Keep it minimal.
Must-have columns
id (uuid default gen_random_uuid())
user_id (uuid, indexed)
title (text)
type (text) — don’t over-enum yet
cloud_id (text, nullable)
tool_id (text, nullable)
workflow_id (text, nullable)
is_starred (boolean default false)
preview_text (text, nullable)
payload_json (jsonb not null default '{}')
thumbnail_url (text, nullable)
created_at / updated_at / last_opened_at
Indexes
(user_id, updated_at desc)
(user_id, last_opened_at desc)
(user_id, cloud_id, updated_at desc)
(user_id, is_starred, updated_at desc)
Important: store cloud_id as the origin cloud so filtering is trivial.
2) API: /api/workspace/items
Yes.
Endpoints
GET /api/workspace/items with query params:
cloud_id, q, sort=recent|updated|name, starred, limit, offset
POST /api/workspace/items
GET /api/workspace/items/:id (updates last_opened_at)
PATCH /api/workspace/items/:id (star/unstar, title)
DELETE /api/workspace/items/:id (optional)
Don’t step on rake: sanitize sort and use parameterized SQL. No string concatenation.
