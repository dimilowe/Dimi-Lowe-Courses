3. Register engine in ENGINE_REGISTRY with gating metadata
In lib/engineRegistry.ts (or equivalent):
export const ENGINE_REGISTRY = {
  // ...
  "thumbnail-analysis": {
    label: "Thumbnail Analysis",
    description: "AI analysis of thumbnails for multiple platforms",
    component: dynamic(() =>
      import("@/components/engines/ThumbnailAnalysisEngine")
    ),
    hasAi: true,
    heavyMode: "single", // so clouds gate it properly
  },
};
This is where the gating metadata lives – not in toolsRegistry.ts.

Set:

"engine_config": {
  "engine": "thumbnail-analysis",
  "variant": "youtube"   // or instagram / tiktok / twitter / facebook / linkedin / pinterest
}
Slug stays the same, URL stays /tools/<slug>, the renderer now loads ThumbnailAnalysisEngine for all of them.
5. Make sure tools table has the correct engine for gating
In tools table row for each of those slugs:
UPDATE tools
SET engine = 'thumbnail-analysis'
WHERE slug IN (
  'ai-thumbnail-coach',
  'instagram-thumbnail-analyzer',
  'tiktok-thumbnail-analyzer',
  'twitter-thumbnail-analyzer',
  'facebook-thumbnail-analyzer',
  'linkedin-thumbnail-analyzer',
  'pinterest-thumbnail-analyzer'
);
That way:
Cloud dashboards know which engine powers them
getToolLockState + ENGINE_REGISTRY["thumbnail-analysis"] handle gating
